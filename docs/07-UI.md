# 07 · 界面与可视化（闸 A 的一部分）

`site/index.html` 是单档页面：内联 CSS、内联 SVG、内联数据，**零外链**（`AC-11`）。
它不是装饰，是这份提交唯一能让人「一眼看出方法对不对」的地方。

## 1. 页面的六个区块

| # | 区块 | 必须让人看到什么 |
|---|---|---|
| 01 | 分数 | 四条同刻度的横条：榜首 22.04 / 记录表 26.85 / 本作品 / 方阵 28.94 |
| 02 | 每段的那条缝 | 31 个 k 段，每段两根柱（方阵 / 本作品），横轴是 k |
| 03 | 装填图 | 12 题真实坐标画出的方块，题号与 L 写在同一张卡上 |
| 04 | 方法 | 三步：盒驱动收缩、45° 非局部动作、预算按段分配 |
| 05 | 逐题对照 | 与记录表差距最大的十题，附「本作品 / 记录」比值 |
| 06 | 复现 | 六条命令，顺序与实际一致 |

## 2. 三条设计判据（不是审美偏好）

1. **数字只能从 `out/results.json` 注入。** 页面里不许出现手写的分数；
   `e2e/site.mjs` 逐卡比对 `figcaption` 里的 L 与 `results.json`，对不上就 FAIL。
2. **装填图必须是真坐标。** 每张卡的 `path.sq` 数量必须等于该题 n；
   少一个或多个都 FAIL —— 这条抓的是「画了示意图而不是画结果」。
3. **不许横向溢出。** 1280 px 与 390 px 两个宽度各查一次
   `scrollWidth − innerWidth ≤ 1`，手机上看不全会 FAIL。

## 3. 为什么不做交互动画

收缩过程是有意思的，但动画会掩盖「合法 / 不合法」这个唯一重要的判据：
一帧卡在重叠状态、用户按了暂停，页面就在说谎。
静态图 + 明确的 L 数字，比一段会骗人的动画诚实。
（记录表那站有可拖拽的 SVG 编辑器，那是给数学家改构型用的；本作品的目标是**报告结果**，不是编辑构型。）

## 4. 配色与字号

- 纸色 `#f7f5ef`、墨色 `#191817`、朱红 `#a63b2a`（本作品）、青 `#2f5d6b`（方块填充）。
- 方块填充用 16% 透明度的青，边框 0.022 单位 —— 相切的边在 190 px 卡上仍然分得开。
- 标题字号 `clamp(34px, 5.2vw, 64px)`；正文 17–21 px；脚注 11.5–13 px。
- 所有数值用 `tabular-nums`，保证一列数字的位数对齐。

## 5. 验收（跟着 `e2e/site.mjs` 走）

- 标题与 h1 含「方寸之间」；`section` ≥ 6。
- 12 张卡 × 每张 `path.sq` 数量 = n；`figcaption` 的 L 与结果档一致（4 位小数）。
- 段图 31 根灰柱 + 31 根红柱。
- 正文里能找到总分与方阵基线（各 4 位小数）。
- 无 console error、无站外请求。
- 1280 / 390 两个宽度都无横向溢出。
- 截图落在 `out/figures/site-1280.png`、`site-390.png`（闸 D 盲读用的就是这两张）。
